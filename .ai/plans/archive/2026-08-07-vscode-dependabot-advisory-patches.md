# VS Code Extension: Patch 10 Open Dependabot Advisories

## Goal

Ten open Dependabot alerts (five high, five medium)
affect transitive dependencies of the VS Code extension,
all recorded in `rlsp-yaml/integrations/vscode/pnpm-lock.yaml`.
Resolve all ten by advancing the extension's existing
`pnpm.overrides` pins to the first patched version of each
affected package, regenerating the lockfile so the
vulnerable versions no longer resolve. The extension's
build, lint, and test suites must continue to pass. The
authoritative closure signal is the GitHub Dependabot alert
state: after the change lands on the branch GitHub scans,
all ten alerts (#39, #40, #41, #43, #44, #45, #46, #47, #48,
#49) must leave the `open` state. The deterministic,
commit-time proof is that the regenerated `pnpm-lock.yaml`
no longer resolves any version inside an alert's vulnerable
range; the GitHub alert re-query is the final confirmation
and is subject to GitHub's re-scan latency. A local
`pnpm audit` is a supporting check, not the target —
`pnpm audit` and GitHub's alert database are distinct data
sources that can disagree.

## Context

All ten alerts are transitive dependency vulnerabilities in
the VS Code extension workspace. None affect the Rust
crates. The affected packages, current resolved versions,
and first patched versions (from the Dependabot alert data,
`gh api repos/{owner}/{repo}/dependabot/alerts`):

| Package | Alerts | Severity | Current | First patched |
|---------|--------|----------|---------|---------------|
| `undici` | #45 | high | 7.28.0 | 7.29.0 |
| `undici` | #46, #47, #48, #49 | medium | 7.28.0 | 7.29.0 |
| `fast-uri` | #44 | high | 3.1.4 | 3.1.5 |
| `postcss` | #39 | high | 8.5.15 | 8.5.18 |
| `postcss` | #43 | medium | 8.5.15 | 8.5.23 |
| `brace-expansion` | #40 | high | 2.1.2 | 2.1.3 |
| `brace-expansion` | #41 | high | 2.1.2 | 2.1.4 |

Choosing the highest patched version per package covers all
alerts for that package at once: `undici ^7.29.0`,
`fast-uri ^3.1.5`, `postcss ^8.5.23`, `brace-expansion@2
^2.1.4`.

**Established mechanism.** The `pnpm.overrides` block in
`rlsp-yaml/integrations/vscode/package.json` is this
project's mechanism for pinning transitive dependencies to
patched versions — the prior security-maintenance plan
(`.ai/plans/2026-07-23-dependabot-followup-ci-and-security-maintenance.md`,
Completed 2026-07-24) established it and it currently pins
ten packages, including `undici`, `fast-uri`, and a
version-scoped
`brace-expansion@2` / `brace-expansion@5`. This plan
advances the stale pins (`undici ^7.28.0`, `fast-uri
^3.1.4`, `brace-expansion@2 ^2.1.2`) and adds a new pin for
`postcss`, which has no override today.

**Reach into shipped artifact.** Of the affected packages,
only `brace-expansion` reaches the shipped extension
runtime — via `vscode-languageclient@9 → minimatch →
brace-expansion` (confirmed with `pnpm why brace-expansion
--prod`). `undici`, `fast-uri`, and `postcss` appear only
in dev/build/publish tooling (`vite`, `vitest`, `esbuild`,
`@vscode/vsce`) and are not shipped. All ten are patched
regardless, because Dependabot flags them and the overrides
mechanism resolves them uniformly.

**Version fields are off-limits.** Per the root CLAUDE.md,
agents must not edit `version = "..."` fields in any
`Cargo.toml`, and release-plz owns version progression.
This task edits only the `pnpm.overrides` block in
`package.json` and the regenerated `pnpm-lock.yaml` — it
does not touch the extension's own `version` field.

**Tooling.** Local `pnpm` is 10.33.2, matching the
extension's declared `packageManager` field; Node is
v24.14.1. Build/lint/test commands are documented in the
root CLAUDE.md under "VS Code Extension".

Key files:

  `pnpm.overrides` block

## Decisions

- **One task, not four:** the manifest edit and lockfile
  regeneration are inseparable — a partial change breaks CI
  — and all four pins are the same kind of change verified
  by the same commands, so splitting them would add commits
  without adding reviewable value.
- **Highest patched version per package:** pinning to the
  highest first-patched version across a package's alerts
  (e.g. `brace-expansion ^2.1.4` covers both #40 and #41)
  closes every alert for that package in one pin rather
  than tracking each advisory separately.
- **`postcss` gets a new override:** it is the only
  affected package without an existing pin; adding one keeps
  all transitive security pins consolidated in the single
  `pnpm.overrides` block rather than introducing a second
  mechanism.
- **Integration tests out of scope for the gate:**
  `pnpm run test:integration` requires a display server
  (xvfb) and exercises the LSP round-trip, not dependency
  resolution; the unit-test/build/lint gate is sufficient
  to prove the override bump did not break the extension.
- **Override consolidation deferred and recorded in the
  follow-up queue:** the `pnpm.overrides` block has grown
  across roughly six prior plans to ten entries, several of
  which (`lodash`, `serialize-javascript`, `form-data`,
  `markdown-it`) this security fix does not touch. Auditing
  whether each existing pin is still required — whether the
  underlying transitive chain has since moved past the
  vulnerable version, making the override redundant — is
  real program-level work, but it is distinct from patching
  the ten open advisories and would expand this plan beyond
  the user's request. To ensure the concern survives this
  plan's eventual `Completed` freeze rather than living only
  as prose here, the lead records it at plan completion as an
  open item under "Open: CI & integrations" in
  `.ai/memory/project_followup_plans.md` — the project's
  established cross-session follow-up queue, which already
  tracks three items surfaced by the 2026-07-23 plan. That
  durable entry is the owning artifact; this keeps the
  security patch tight and independently reviewable while the
  consolidation concern remains queued for a future session.

## Non-Goals

- Bumping direct dependencies or devDependencies in
  `package.json` beyond the four override pins — only the
  transitive pins flagged by Dependabot are in scope.
- Any change to the Rust crates, their `Cargo.toml` files,
  or `Cargo.lock`.
- CI workflow changes — the prior plan addressed CI pnpm
  version and lockfile-in-CI concerns; this plan is purely
  the advisory patches.
- Auditing or pruning the existing `pnpm.overrides` entries
  this plan does not touch (`lodash`, `serialize-javascript`,
  `qs`, `form-data`, `markdown-it`, `js-yaml`,
  `brace-expansion@5`) to check whether any pin is now
  redundant — deferred and recorded in the follow-up queue
  at plan completion (see Decisions).
